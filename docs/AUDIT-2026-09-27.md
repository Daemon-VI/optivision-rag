# Repository audit — 2026-09-27

Phase 0 of the move toward a model-agnostic compression layer. This document
records what the code base does today, what was re-measured, and which claims in
circulation are measured, external or projected. Nothing here was changed to make
a number look better; every figure in the "measured" column was reproduced on
this date from the encode caches with the code at `origin/main` (f3949ea).

Three labels are used throughout, and they are never mixed:

| label | meaning |
|---|---|
| **MEASURED** | produced by this repository's code on real encoder output, reproducible from the caches |
| **EXTERNAL** | reported by a paper or model card; not reproduced here |
| **PROJECTED** | an estimate that nobody has measured; a hypothesis to test |

## 1. What OptiVision does today

A fixed, ColPali-shaped pipeline:

```
page image ─► ColVLM encoder ─► PageEncoding ─► TokenPruner ─► PrunedPage ─► Compressor ─► CompressedPage ─► index
              (colpali-engine)   [n,128] f32    spatial +       [k,128] f32   none|binary|   uint8 codes       numpy (exact MaxSim)
                                  + PatchGrid    redundancy                    int8|lloyd2                      or Qdrant (MAX_SIM)
                                  + page image
```

| component | file | what it really does |
|---|---|---|
| data model | `types.py` | `PageEncoding` (vectors + `PatchGrid` + image size + protected "text" tokens), `PrunedPage`, `CompressedPage` (codes + byte accounting against a float32 baseline) |
| encoders | `encoders/colvlm.py` | colpali-engine backends `colsmol`, `colsmol-500m`, `colpali` (merged v1.3), `colqwen2`; detects the patch grid, including Idefics3 tiling (13 runs of 64 for ColSmol on A4) |
| test encoder | `encoders/synthetic.py` | hashed word vectors on a grid; plumbing only, metrics saturate |
| spatial pruning | `pruning/saliency.py`, `spatial.py` | ink density + edge energy per grid cell on the page pixels; keep by threshold (with dilation) or by fixed top-k ratio; `min_keep` floor |
| retrieval-space saliency | `pruning/codebook.py` | patch score = number of probe directions it wins (farthest-point, random or k-means probes) |
| redundancy pruning | `pruning/redundancy.py` | greedy single-pass leader clustering in saliency order, cosine ≥ 0.92, cluster → renormalised mean |
| quantization | `compression/` | `binary` = sign bits (32x); `int8` = fixed full-scale 0.5 (4x); `lloyd2` = random rotation + 2-bit Lloyd-Max with corpus-fitted mean/σ (16x); asymmetric scoring (float query vs decoded document) |
| exact index | `index/numpy_index.py` | concatenated codes + offsets, `np.maximum.reduceat` MaxSim, memory-bounded streaming decode |
| Qdrant | `index/qdrant_index.py` | one point per page, `MultiVectorComparator.MAX_SIM`; default sends *float* vectors and lets Qdrant apply `BinaryQuantization(always_ram)` |
| orchestration | `pipeline.py` | `OptiVisionRAG.build()` / `.search()`, optional float-cache rerank |
| benchmark | `bench.py` | encode once (`EncodedCorpus` cache incl. 512 px grayscale pages), replay fixed `Variant` rows, nDCG/Recall/Hit/MRR, Kendall tau vs baseline, JSON + Markdown |
| CLI | `cli.py` | `make-corpus`, `fetch-vidore`, `index`, `search`, `stats`, `bench`, `explain`, `init-config` |

## 2. Couplings that block the universal vision

1. **The data model is image-shaped.** `PageEncoding` requires a `PatchGrid` and an
   image size. A text ColBERT document, a precomputed vector file, or a video has
   neither, so nothing downstream can accept them.
2. **The pipeline is one fixed recipe.** `TokenPruner` hard-codes spatial →
   redundancy; `Compressor` picks one codec. There is no way to compose, reorder
   or add stages, and no dimension-reduction stage at all.
3. **Nothing chooses a configuration.** The system never looks at quality when it
   compresses. `bench` measures a hand-written list of variants after the fact,
   against ground-truth labels only, on the same queries it reports.
4. **Spatial pruning needs pixels.** It is useless on dense pages
   (measured 1.03x on InfoVQA) and impossible without the image.
5. **int8's full-scale constant is tuned to 128-d unit vectors.** `INT8_SCALE = 0.5`
   assumes components near 1/√128. A 3072-d unit vector's components are ~5x
   smaller, so the same constant would use roughly a fifth of the int8 range.
   Analytical finding, not yet measured on a wide model (none is available locally).
6. **Byte accounting assumes a float32 baseline** (`raw_nbytes(dtype_size=4)`).
   Several current models are served in bf16/fp16, so "compression vs float32" and
   "compression vs what you store today" differ by 2x and must be stated.
7. **Qdrant accounting is client-side.** In the default `server_quantized` mode Qdrant
   stores the float vectors on disk plus binary codes in RAM; the reported index
   bytes are the pipeline's codes, not Qdrant's footprint.

### 3.1 DocVQA labels were rebuilt

The DocVQA cache had no `queries.json` on this machine. It was rebuilt from the
public dataset rows (`scripts/rebuild_vidore_qrels.py`, no images downloaded) with
the same rule as `corpus.load_vidore_subset`. The 451 rebuilt query strings are
identical, in order, to the strings stored in the cache, and the float baseline
reproduces the committed 0.5841 exactly. (A first attempt decoded the API response
in the Windows code page and mangled curly quotes; the script now decodes UTF-8.)

### 3.2 Two findings from the replay

- **A latent bug in the exact index.** `NumpyIndex._segment_maxsim` clamped a
  `reduceat` start equal to the row count down to the last row. When the last
  page of a block is empty, that silently drops the final vector of the page
  before it: a page whose best match is its last vector scored 0.0 instead of
  1.0 in a three-vector reproduction. It never fired in a published run, because
  pruning keeps at least 16 vectors per page, and re-running E1 after the fix gives
  byte-identical rankings. Fixed with a regression test (`tests/test_index.py`).
- **The 2-bit codec's DocVQA number depends on how it is run.** `bench` gives
  `lloyd2-only` 95.2% on DocVQA; `docs/RESULTS.md` quotes 97.0% from
  `scripts/review/codec_ladder.py`. The two fit the codec and break ties
  differently. Unexplained so far; treat the 2-bit DocVQA figure as uncertain by
  about two points until the new benchmark resolves it.

### 3.3 Measured facts that constrain the design

- Pixel spatial pruning keeps 1000 of 1031 ColPali tokens on InfoVQA. On dense
  pages it does nothing. **MEASURED**
- Redundancy merging at cosine 0.92 takes InfoVQA from 1000 to 618 tokens at
  99.7% retention. Merging, not dropping, is where the reduction came from. **MEASURED**
- 74% (InfoVQA) and 66% (DocVQA) of patches win at least one MaxSim across the
  query set, so query-agnostic *dropping* has little to remove on real pages. **MEASURED**
  (`reports/winner_stats_*`)
- Random probe directions select tokens as well as designed ones. **MEASURED**
- int8 is lossless on every run; binary costs 1.6 to 12.1 points depending on
  encoder and corpus; the rotated 2-bit codec sits between them. **MEASURED**
- Rescoring a binary top-10 shortlist with int8 recovered 99.1% (E1), 100% (E3)
  and 99.9% (ColSmol InfoVQA) of float nDCG@5 — without any pruning, and never on
  ColPali ViDoRe. **MEASURED, narrow**

## 4. Status of the claims in the previous proposal

The proposal written earlier in this session combined external results with this
repository's codec numbers. None of its headline figures was measured here.

| claim | status | why |
|---|---|---|
| "Balanced: 160x RAM at 97–98% on any model" | **PROJECTED** | multiplies an external merge curve (AnchorFold, attention-guided) by a rerank figure measured only without merging; the multiplication itself is an untested assumption |
| "Aggressive: 320x at 96.5–98.5% with a per-model adapter" | **PROJECTED** | rests on MarginMerge's trained network; no adapter exists here |
| "6,400–10,240x at 92–97.5% for 2560–4096-d models" | **PROJECTED** | no wide-model embeddings available locally; the projection numbers come from NVIDIA's *trained* heads on ViDoRe V3 nDCG@10, a different metric and benchmark |
| per-model tables for 16 visual models | **PROJECTED** | ColQwen2.5's external curve was used as a proxy for ten models |
| training-free merging keeps 97.8–98.9% at 5x | **EXTERNAL** | AnchorFold paper; its closest training-free, attention-free baseline ("semantic clustering") reports 97.0% on ColPali ViDoRe V1 and 90.4% on V2 at 5x |
| binary + int8 rerank recovers 99–100% | **MEASURED only without merging, and not on ColPali ViDoRe** | see §3.2 |
| "works on every multi-vector model" / "universal" | **UNSUPPORTED** | measured coverage is ColPali-v1.3 and ColSmol-256M |
| sentence-transformers `MultiVectorEncoder` loads all Col* and ColBERT models | **EXTERNAL** | model cards; not installed or tested here |
| "calibration guarantees the target" | **UNSUPPORTED as worded** | calibration can only promise the target on the calibration queries; held-out behaviour has to be measured |

## 5. What to build first, what to reuse, what to redesign

**Reuse as-is:** the codecs (`pack_bits`, `unpack_signs`, `lloyd2`), the exact
MaxSim kernel (`NumpyIndex._segment_maxsim` / `reduceat`), the metrics, the
encoders, the encode-cache format, the Qdrant backend, the CLI and the existing
`bench` table. They are correct and tested, and the new layer calls them.

**Wrap, don't rewrite:** `prune_redundant` and the pixel saliency become stages in
a composable pipeline. The old `OptiVisionRAG` and `bench` keep working unchanged.

**Redesign:**
- a model-free data model (`MultiVectorRepresentation`, `MultiVectorCorpus`) that
  needs only vectors, with optional grid positions, protected tokens and metadata;
- stages with one contract (`fit` / `transform`), so token reduction, projection
  and quantization compose in any order the math allows;
- quality-aware selection: evaluate candidate pipelines against the uncompressed
  baseline on a calibration split, report on a separate validation split;
- an int8 scale that does not assume 128 dimensions.

**Order of work:** representation (Phase 1) → stages + pipeline with an
equivalence test against the old recipe (2) → training-free merging (3) →
calibration with splits (4) → Pareto reporting (5) → projection (6) → quantizer
fixes (7) → tiered rerank (8) → adapters (9) → benchmark matrix (10).

## 6. The benchmark that decides whether the new system works

On every locally available (encoder, corpus) cell — ColPali × {InfoVQA, DocVQA,
generated} and ColSmol × generated:

1. Split queries into a calibration half and a held-out half with a fixed seed.
2. For targets 0.99, 0.97 and 0.95 of float nDCG@5, let the calibrator choose the
   smallest configuration on the calibration half only.
3. Report, on the held-out half: achieved retention with a bootstrap CI, bytes per
   page, vectors per page, and the ratio to the best fixed configuration that
   exists today (`prune+int8`, `optivision`, `binary-only`).

It works if (a) held-out retention meets the target within its CI, and (b) the
chosen configuration is smaller than today's fixed configurations at equal or
better held-out quality. Identity pipelines must reproduce the float baseline
scores exactly, and the refactored old recipe must reproduce the old table.

Coverage is reported as exactly the cells run. Anything else is future work.
